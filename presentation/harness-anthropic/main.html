Harness Design · The Shift
The unit of work has changed. We are no longer optimizing for a clean single response — we are designing for agents that wake up in an unfamiliar repo, finish a feature, and hand off to a future version of themselves. That shift is what makes harness design suddenly load-bearing.

The Failure Modes · Five New Ways to Fail

New failure modes that emerge with time.

  1. 01

    Context anxiety

    Models wrap work up prematurely as the context fills toward its limit.

  2. 02

    Premature victory

    The agent declares “done” after partial work — tests skipped, edge cases ignored.

  3. 03

    Opaque handoffs

    The next session must guess what the previous one did, why, and where it stopped.

  4. 04

    Self-flattery

    Agents grade their own mediocre output as excellent — the bar moves with the writer.

  5. 05

    Inherited breakage

    Later sessions waste hours debugging bugs the earlier sessions silently introduced.

Harness Design · Failure Modes
These are the five failure modes that show up once you stretch an agent past a single context window. Each one motivates a specific piece of the harness. If your agent doesn't run long, you don't need most of this.

Failure Mode · 01 · Context Anxiety

Models get nervous
near their context limit.

Claude Sonnet 4.5 starts wrapping work up prematurely as context fills. The instinct is to compact — summarize the conversation in place. Compaction alone doesn't fix it; the model still senses the long history and behaves accordingly.

The fix: a full context reset with a structured handoff — not a summary, but a fresh shift starting from artifacts the previous shift left behind.

Counter-conventional: reset beats compact for long sessions. The intuition is wrong because the model isn't responding to length — it's responding to perceived remaining capacity.

A“Context resets were essential to the harness design.”

BCompaction = summarize in place. Reset = end the session, hand off artifacts.

CAnthropic cut cost 37% by replacing compaction with periodic resets — no quality drop.

Harness Design · Context
This is one of the most counter-conventional findings. The instinct is to compact — summarize the conversation in place. Anthropic found that doesn't eliminate the anxiety, because the model still senses the long history. A full context reset with a structured handoff actually works better.

Pattern · 01 · Handoff Beats Memory

Write the handoff a new shift would need.

  1. i

    init.sh — so the agent doesn't relearn setup

    Bootstrap script per project. New shift runs it; ready in seconds, not minutes.

  2. ii

    claude-progress.txt — what was done, and why

    Append-only log. Forces the model to articulate decisions, which it can re-read.

  3. iii

    Git history with descriptive commits

    One commit per feature, written for the next agent to read — not for the next human.

  4. iv

    JSON feature list — 200+ entries, pass/fail

    JSON, not Markdown, because the model is less likely to “tidy” structured data.

  5. v

    One feature per session — never one-shot the app

    The discipline that makes the rest of the artifacts useful.

Harness Design · Handoffs
The inspiration here is human: what does a software engineer leave behind so the next shift can pick up cleanly? That metaphor drove the whole initializer-agent design for the claude.ai clone build. JSON, not Markdown, because the model is less likely to "tidy" structured data.
Part Two — Anthropic's Three-Agent Pattern

Separate the doer
from the judge.

G
Generator · writes the work
Writes the code, the design, the spec. Optimized for production, not judgment.
E
Evaluator · holds the bar
Different agent, different prompt — grades the generator against concrete criteria. Adversarial by design.
P
Planner · expands the brief
Turns a short user prompt into a full spec the generator and evaluator can act on.

Why three, not one — “separating the agent doing the work from the agent judging it proves to be a strong lever.” The architecture deliberately echoes generative adversarial networks; self-evaluation fails because the bar moves with the writer.

Harness Design · Roles
This is the central pattern of the primary post. Self-evaluation fails — models praise their own work. The fix is structural: a different agent, with different prompting, holds the bar. The architecture deliberately echoes generative adversarial networks.

Pattern · 02 · Criteria Are a Steering Wheel

Concrete criteria, not vibes.

Four grading axes for frontend quality — and a warning about how wording steers the generator before the evaluator ever runs.

  1. 01

    Design quality

    Coherence, mood, identity — does the work feel like one thing made by one mind?

  2. 02

    Originality

    Custom decisions vs template defaults — how much of the output is the model's own taste?

  3. 03

    Craft

    Typography, spacing, color, contrast — the things a careful eye would notice on a second pass.

  4. 04

    Functionality

    Does it actually work for the user — or just look like it would?

Wording warning — phrasing like “museum quality” pulled designs toward visual convergence. Criteria shape output before evaluation; pick verbs and adjectives carefully.

Harness Design · Criteria
Subjective quality is the hardest thing to evaluate, so Anthropic forces it concrete. Phrasing like "museum quality" actually pulled designs toward visual convergence. Criteria are not neutral — they shape output even before the evaluator runs.

Pattern · 03 · Agree Before You Build

Agree what “done” means
before you build.

Sprint contract — the per-chunk agreement between generator and evaluator on what success looks like. Negotiated up front, not discovered mid-run.

Concrete enough to verify — one game-maker sprint had 27 explicit criteria. Loose enough not to over-engineer — the contract covers this chunk, not the whole project.

The missing layer between “build me a DAW” and a passing test. Without it, the evaluator and generator argue from different specs.

AOne sprint, one contract. Adjust the contract between sprints, not within them.

BOver-specifying the whole project up front kills creative leaps — spec each chunk.

CThe contract is also a handoff artifact: future shifts know what “done” meant.

Harness Design · Sprint Contract
A sprint contract is Anthropic's term for the per-chunk agreement between generator and evaluator on success conditions. It's the missing layer between "build me a DAW" and a passing test — concrete enough to verify, loose enough not to over-engineer.

What Not To Do · Explicit Anthropic Warnings

Antipatterns Anthropic calls out.

  1. 01

    Self-evaluation without an external judge

    The bar moves with the writer. Always pair generator with a separate evaluator.

  2. 02

    Over-specifying implementation up front

    Kills creative leaps. Specify each chunk via a sprint contract, not the whole project.

  3. 03

    Compaction alone for context management

    Doesn't fix context anxiety. Use full resets with structured handoffs.

  4. 04

    Generic prompts for design work — output goes bland

    “Museum quality” converges; pick words that diverge.

  5. 05

    “It is unacceptable to remove or edit tests because this could lead to missing or buggy functionality.”

    The strongest single line in either post. Make sure the audience hears that one.

Harness Design · Antipatterns
These are the explicit warnings across both engineering posts. The strongest language: "It is unacceptable to remove or edit tests because this could lead to missing or buggy functionality." Make sure the audience hears that one.

Part Three — Infrastructure · Managed Agents

Decouple brain, hands, session.

B
Brain · Claude and its harness
The reasoning loop. Stateless across sessions; resumes via wake(sessionId).
H
Hands · sandboxes
Called via execute(name, input). Interchangeable; never holds credentials.
S
Session · durable event log
Append-only, persisted outside the harness. Not Claude's context window.

Why decouple — each layer can fail, restart, or scale independently. Brain crashes — rehydrate from the session. Sandbox dies — spin up a new one. The session outlives everything.

Managed Agents · Architecture
The third post is the platform layer. Anthropic's managed-agents service is what you get when you take the harness lessons and turn them into hosted infrastructure. The decoupling means each piece can fail, restart, or scale independently.

Takeaways · What to Take Back to Your Team

Six things to act on Monday.

  1. 01

    Design for context resets, not just compaction

    Reset beats summarize for long-running work. Ship the handoff, not the history.

  2. 02

    Separate generator from evaluator — always

    Self-evaluation fails. Two different agents, two different prompts, one moving bar.

  3. 03

    Make criteria concrete; wording is a steering wheel

    Pick verbs that diverge. “Museum quality” converges; better adjectives pull harder.

  4. 04

    Hand off through artifacts a new shift could read

    init.sh, progress log, JSON feature list. Written for the next agent, not the next human.

  5. 05

    Audit harness assumptions every model bump

    Dead weight is invisible until you measure cost. Strip what the new model no longer needs.

  6. 06

    Decouple brain, hands, session when you scale

    Each layer fails, restarts, scales independently. The session is the system of record.
